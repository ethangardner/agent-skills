# Variations

Read this when the user asks for one of these modes, brings more than one
challenge, or when you're deciding whether 25/10 Crowdsourcing is even the
right structure for what they brought.

## 25/10 vs. Wise Crowds — which one

Both borrow the word "crowd" and both use an invented cast instead of one or
two voices, which is exactly why they get confused for each other. The
mechanisms don't overlap at all.

- **Wise Crowds is consultation.** Three or four consultants talk to each
  other, in dialogue, about the user's one problem, while the user listens
  without replying. A separate satellite layer then reports on how that
  conversation went. The output is a small number of concrete next moves plus
  a read on the conversation's own blind spots. There is exactly one
  challenge in play, examined from several angles in real time.
- **25/10 Crowdsourcing is generation plus rating.** Six to eight personas
  each write one bold idea of their own — nobody discusses anybody's idea, no
  persona ever responds to another persona's card — and then a five-rater,
  1-25 scoring pass surfaces which ideas the crowd actually preferred. The
  output is a ranked field of ideas, several of which weren't the user's to
  begin with, with a receipt for why each one scored the way it did.
- **The tell, in one sentence:** if the user wants a handful of people
  thinking *together* about their problem, that's Wise Crowds; if they want
  a pile of *independent* ideas rated and ranked with no discussion at all,
  that's 25/10 Crowdsourcing.
- **Don't run 25/10 just because the user said "crowd" or "wisdom of the
  crowd."** Those phrases show up naturally when someone wants triangulated
  advice on one problem, which is Wise Crowds. Reach for 25/10 specifically
  when the ask is about *volume of ideas* and a fast way to prioritize among
  them, not about depth on one already-chosen challenge.
- **If genuinely unsure, ask what they have in hand.** One problem they want
  worked over → Wise Crowds or Troika Consulting. Several possible ideas, or
  no idea yet and a wide net wanted → 25/10 Crowdsourcing.

## Speed 25/10

Compress the cast and the rounds together: four personas instead of six to
eight, and three ratings per card instead of five (max possible 15, not 25 —
say so explicitly when you report scores, so the numbers aren't mistaken for
the full-scale version). Keep the countdown format even at this scale; it's
cheap and it's what keeps the reveal from reading like a spreadsheet.

Use this when the user has said they're short on time, wants a quick pulse
read rather than a considered prioritization, or is triaging across several
challenges in one sitting and each one only needs a fast pass (see
round-robin, below). Don't compress the variance rule — a fast crowd that
still agrees with itself on everything is worthless regardless of how few
rounds it ran.

## Multiple challenges from the user

If the user has more than one challenge and wants ideas generated for each,
run each as its own complete pass — Phase 0 through Phase 5 — rather than
pooling every idea from every challenge into one giant countdown. A crowd
rating "how to onboard faster" ideas against "how to cut costs" ideas in the
same pile produces a comparison that means nothing; the personas' stances
don't transfer cleanly across unrelated challenges, and a high score on one
domain isn't commensurate with a high score on another.

Keep the same cast across challenges rather than recasting each time — a
persona who's now written and rated cards on two of the user's challenges
starts producing sharper first steps and sharper reasons for a score, the
same benefit multi-round Troika and Wise Crowds sessions get from a
carried-over panel. If the challenges are genuinely unrelated domains where
the same skeptic-or-dreamer framing wouldn't fit both, recast — but that's
the exception.

Between challenges, a one-line transition naming the next challenge and
moving straight to Phase 1 is enough. Don't re-run Phase 0's full invitation
each time.

## Fewer or more cards from the user

The base structure has the user contribute exactly one card in Phase 1. If
the user wants to contribute several bold ideas for the same challenge
rather than one, let them — treat each as its own card entering the same
pool, rated by the same crowd under the same five-rater rule, and reveal them
in the same countdown alongside the persona cards. This doesn't change the
mechanism at all; it just means the "who has a 25" reveal might surface two
of the user's own cards instead of one, which is useful information in its
own right (which of the user's several instincts does the crowd actually
prefer).

Resist the opposite pull — running the whole structure around only the
personas' cards with no card from the user at all. The user contributing a
real card, scored with the same rigor as everyone else's, is what keeps this
a session about the user's challenge rather than a demo of invented
personas talking past each other.
