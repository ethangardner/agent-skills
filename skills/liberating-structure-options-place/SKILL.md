# Options Place

A self-organizing-agenda structure, adapted so one language model can run it
with one user instead of a room. The original seats ten or more people who
each propose their own breakout session, post it to a shared board, and then
choose — individually, by walking to a room — which of several *parallel*
sessions to attend, guided by one rule: go to where you are learning or
contributing.

## The honest scale-down

None of that survives contact with a single user and a single model in the
form it was designed in. Say this plainly rather than pretending otherwise:
there is no crowd generating topics, so the "agenda" is just whatever is
already competing for the user's attention. And there is no parallelism —
a person cannot actually be in two breakout sessions at once, so "choosing
which session to attend" cannot mean what it means in a room of fifty people
splitting into five groups.

What's worth preserving, and what this skill actually runs on, is two things
from the original that don't depend on there being a crowd at all:

1. **The self-selection test.** "Go to where you are learning or
   contributing" is really an honesty check about what's worth someone's
   actual time, stripped of politeness or obligation. That check works just
   as well pointed at one person's own list of competing topics as it does
   pointed at a room full of strangers' proposals. This is the one mechanism
   worth carrying over, and it's what makes this different from just working
   through a to-do list in order.
2. **The closing synthesis.** The original explicitly names noticing
   connections across sessions as one of the real payoffs of the structure —
   something a person doing five unrelated meetings in a row wouldn't get.
   That's cheap to preserve here and worth doing deliberately rather than
   skipping.

What's different, and should stay different rather than be faked: sessions
run **sequentially**, one at a time, not in parallel breakout rooms. And the
"agenda" is the user's own competing topics, not a crowd's independent
proposals — which also means the honest move is fewer topics per sitting than
the original, not more. The original's parallelism let fifty people cover
fifteen topics in an hour. One person covering four topics well in one
sitting is the ceiling here, and that's a feature of staying focused, not a
consolation prize.

If the user wants the fuller flavor with invented "other attendees" proposing
their own related topics, that's covered in `references/variations.md` — but
it's explicitly synthetic and explicitly still sequential. Default to the
solo mode below unless asked.

## Phases

Run these in order. Stop where marked and wait for the user — the phases
exist to keep the user actually doing the prioritizing and actually engaging
with one topic before the next arrives, not reading a wall of text covering
everything at once.

### Phase 0 — Establish the frame

Give the structuring invitation, in your own words, close to this spirit:
*"What's competing for your attention right now — the open questions,
decisions, or threads that keep coming back to mind?"* If the user already
came in with a specific set of things they want to work through, skip
straight to Phase 1 with those.

**Stop.** Wait for the list.

### Phase 1 — Build the agenda

Get the full list down before evaluating any of it — this mirrors the
original's sticky-note board, where topics get posted before anyone starts
picking. Don't prune or comment yet, even if one item obviously deserves
more time than another. A short title per topic is enough; resist the pull
to have the user fully explain each one here, that's what the mini-sessions
are for.

**Stop.** Confirm the list is complete before moving on.

### Phase 2 — The self-selection test

Apply the rule honestly to each topic on the list: **would spending real time
on this teach you something you don't already know, or move something you
actually control?** If the honest answer to both halves is no, it doesn't
earn a session — not because it isn't real or important, but because a
session here can't do anything for it that thinking about it alone hasn't
already done.

Say what you see for each topic — where it passes, where it doesn't, and why
— rather than silently filtering. The user may disagree with your read, and
they get the final call on their own topics; the point of doing this out
loud is to make the filter honest, not to make it unilateral.

Prioritize down to **two to four topics** for this sitting. If more survive
the test than that, say so and ask the user to rank rather than running six
sessions at shallow depth — the original could afford breadth because a
crowd was doing it in parallel; one person doing it sequentially can't, and
pretending otherwise produces a shallow pass across everything instead of
real focus on a few.

**Stop.** Let the user confirm or adjust the final short list.

### Phase 3 — Run the sessions, one at a time

For each surviving topic, in the order the user prefers (or the order
listed, if they don't care): run a focused mini-session on that topic alone.
Treat yourself as the session leader the way a proposer in the original
would be — come in with a plan for the ~15-minute equivalent, not just an
open "so, tell me about this." Ask sharpening questions, surface what the
user hasn't said yet, push toward whatever this topic actually needs (a
decision, a next step, clarity on what's actually being asked) rather than
a generic conversation.

Cover exactly one topic per message. Do not preview or fold in the next
topic while still working the current one — that's the mechanism that got
lost by going sequential, so protect it deliberately: single-topic focus is
the whole point of a "session," even a short one.

**Stop after each topic.** Let the user actually engage with it before the
next one starts. Moving on before they've had a real exchange on this one
turns the whole structure into a list you read down rather than sessions
they attend.

### Phase 4 — Synthesis across sessions

Once every topic has had its session, close by naming what connects them —
a shared root cause, a decision that unlocks more than one topic, a pattern
in what the user is avoiding or gravitating toward, resources or time that
two topics are quietly competing for. This is not a summary of what was said
in each session; it's specifically the connective tissue *across* them, the
thing a person doing four separate unrelated conversations wouldn't
naturally notice. If there genuinely isn't a connection, say that plainly
rather than manufacturing one — see Judgment calls below.

Close by asking what, if anything, the user wants to carry forward as an
actual next step from the sitting as a whole.

Further variations — including a synthetic "crowd" mode with invented
attendees proposing their own topics — are in `references/variations.md`.
Read it when the user wants the fuller unconference flavor rather than
working their own list.

## Things that break the session

- **A shallow pass across every topic instead of real focus on fewer.**
  Running six thin sessions because the user listed six topics defeats the
  test in Phase 2 — the whole point of narrowing is to give the surviving
  topics real time.
- **Skipping the synthesis.** It's tempting to end after the last topic's
  session, since it feels like the work is done. It isn't — the original
  names cross-session connection as a real benefit, and it only happens if
  you deliberately look for it at the end, not while heads-down on any one
  topic.
- **Forcing a topic through that fails its own test.** If a topic doesn't
  pass "would this teach you something or move something you control," don't
  run it anyway just because the user proposed it or seems attached to it.
  Say plainly that this one doesn't earn a session and why, and let the user
  push back if they disagree.
- **Bundling topics into one message.** A message that covers two topics at
  once, or previews Phase 3's next topic while still in the current one, has
  quietly turned this back into a single conversation with subheadings
  instead of a sequence of sessions.

## Judgment calls

If the user really only has one thing on their mind, say so and point
elsewhere — Options Place is built around competing topics, and running it
on a single topic just adds ceremony around what Troika Consulting (for
outside perspective on one problem) or a direct conversation would do more
directly.

If, at Phase 4, the mini-sessions genuinely don't connect — four unrelated
topics that happen to share a calendar but nothing else — say that rather
than inventing a through-line. A forced synthesis is worse than none; the
honesty of the Phase 2 test should carry through to the close.

If the user's list turns out to be one big topic wearing several names (three
"different" work worries that are all actually about the same looming
decision), say so at Phase 1 or Phase 2 rather than running three sessions
on what's really one thing — that's not a failure of the structure, it's
exactly the kind of thing the self-selection test is supposed to catch.
