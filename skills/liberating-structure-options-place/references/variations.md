# Variations

Read this when the user wants something other than the solo default — most
often the fuller unconference flavor with other voices proposing topics.

## Crowd mode (synthetic attendees)

The original gets roughly three proposals per ten participants, from people
the user never has to invent themselves. To approximate that fuller flavor,
invent a handful of "other attendees" — colleagues, stakeholders, family
members, whoever fits the theme and whatever the user has told you about
their context — and have each of them propose their own topic for the board,
in addition to the user's own.

**This is explicitly synthetic, and that's fine here.** Say so up front if
the user seems unclear on it. Unlike Discovery and Action Dialogue, where
inventing a person's practices would hand the user fabricated intel about
their real team, the personas here don't claim to represent what any real
person actually thinks or wants — they exist purely to generate a wider
spread of topics for ideation, the way a facilitator might toss a few
prompts onto a blank board to get things moving. Don't let the personas
drift into sounding like a report on real colleagues' real opinions; keep
them clearly framed as invented, and don't attribute a persona's proposed
topic to the real person they're loosely modeled on if you name one.

Run it as:

1. **Cast the attendees.** Two to four is enough — more and the board gets
   noisy without adding real variety. Give each a one-line stance or
   interest relevant to the user's theme ("Priya, who only cares whether
   this ships on time"; "the persona modeling your co-founder, focused on
   runway"). Say plainly that these are invented.
2. **Populate the board.** Each persona proposes one topic, in character,
   the way a real attendee would post a sticky note — a title and a line on
   why they want to explore it. Add these alongside the user's own topics
   from Phase 1.
3. **Run the self-selection test across the whole board**, the user's own
   topics and the personas' proposals together. A persona's topic can
   survive the cut and get a real session if it genuinely passes "would this
   teach the user something or move something they control" — it doesn't
   get a session just because it's colorful or because a persona is
   attached to it. Most of the time a persona's proposal will fail the test
   outright (it's their concern, not something the user controls), and
   that's fine — the value was in surfacing an angle the user might not have
   listed themselves, not in guaranteeing it a slot.
4. **Sessions still run sequentially, one at a time**, exactly as in the
   solo mode. See below for why.

## Why true parallel sessions still aren't attempted here

Even with a full invented crowd on the board, the fix doesn't extend to
running sessions in parallel. The entire value of parallel breakout rooms in
the original is that *different people* are in each room simultaneously,
each getting the session they chose. Here there is exactly one attendee —
the user — no matter how many personas proposed topics. Simulating five
rooms running at once and asking the user to somehow attend all of them
would just be five topics narrated in one message, which is the single
worst failure mode this whole family of skills is built to avoid: a wall of
text standing in for a structure. The crowd variant makes the *board* fuller
and more interesting to filter; it doesn't and shouldn't try to make the
*attending* concurrent. Keep Phase 3 sequential, one topic per message, Stop
between each, exactly as in the default mode.

## Lean Coffee mode

The source material notes a smaller-group variant, Lean Coffee, that runs
fast 7–10 minute sessions across several topics rather than fewer longer
ones. Translate this as: skip straight from Phase 1 to short, brisk
mini-sessions — a couple of sharp questions and a quick landing point per
topic, rather than the fuller treatment in the default Phase 3 — and allow
more topics through the Phase 2 filter than the usual two-to-four cap, since
each one is costing much less time. Use this when the user says they want to
triage a longer list quickly rather than go deep on a few things.

## Reopening the board

The source material also suggests reopening the board for a further round
rather than stopping after one pass. If, after Phase 4's synthesis, new
topics have surfaced — often the synthesis itself surfaces one nobody named
going in — offer to run a second, shorter pass: back to a scaled-down Phase
1 with just the new topic(s), through the self-selection test, then a
session or two, then fold the result into an updated synthesis rather than
starting the whole close over. Don't offer this reflexively after every
session; it's worth it when the synthesis genuinely turned something up, not
as a default extension.
