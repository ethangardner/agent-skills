# Variations

Read this when the default solo, facilitator-mode session (SKILL.md) isn't
the right shape for what the user actually needs.

## Facilitating a real group the user is hosting

If the user says they have real other people — a live meeting, a remote
team standup, a workshop, a classroom — don't run the synthetic version on
them. Their job changes from "answer the widened question" to "run this
structure for the room," and your job changes from host-of-one to
facilitation-script writer.

Give them, in order:

1. **The framing invitation** to read aloud or post, matched to their
   question (see Phase 0 in SKILL.md for the shape of it).
2. **A timer script**: roughly 1 minute individual silent writing, 2 minutes
   in pairs, 4 minutes in fours, 5 minutes whole-group harvest — about 12
   minutes total, plus a short intro. Tell them to hold the times strictly;
   loosening the clock is the most common way this collapses in practice,
   because it lets the loudest voices refill the silence the structure is
   built to protect.
3. **The exact prompts** to give at each transition: "What opportunities do
   YOU see...", "Share and build on your ideas with your partner", "Share
   your pair's most important ideas in your group of four", "What is one
   idea that stood out in your conversation?"
4. **A warning about the harvest**: coach them to ask each group of four for
   *one* standout idea, not a full report-out. Groups will default to
   reporting everything unless asked explicitly for the single most
   interesting thing.

You are not playing any role in this mode — no host voice, no imagined
partner. You're handing the user a script they run themselves.

## Async / remote — the Chatterfall variant

For a distributed or async group, the whole-group harvest (Phase 4) can run
as "Chatterfall": instead of a few groups reporting out loud, every
participant privately writes their one standout idea, and then everyone
posts simultaneously (in chat, a shared doc, a form) on a cue, so nobody's
idea is anchored by seeing others' first. The effect stands in for the
synchronous "several tables report" harvest when people aren't in a room.

If the user is running this for a remote team, offer Chatterfall specifically
for Phase 4 rather than trying to force a live report-out over chat, which
tends to just replicate whoever types fastest dominating, the exact power
imbalance the structure exists to avoid.

## Chaining multiple rounds

If the user has several related questions to widen — not just one, and not
different enough to warrant separate sessions — run Phase 0 through 4 for
each question in sequence, resetting to individual silence each time rather
than letting momentum from question one bleed into question two's "silent"
reflection. After the last round, offer a short closing pass: what pattern
showed up across all the harvested ideas, if any did. Don't manufacture a
cross-question pattern if the questions were genuinely unrelated — a set of
independent, unconnected harvests is a fine outcome.

## The fully synthetic mode (explicit opt-in only)

If the user explicitly wants distinct invented partners with their own
competing ideas — closer to how Impromptu Networking or Wise Crowds would
run it — that's available, but it is not this skill's default for good
reason (see "No invented personas" in SKILL.md). If you run it:

- Cast one pair-partner and one quad (two more voices, cast for real
  contrast, the way Troika casts its consultants) rather than reusing the
  same invented voice at every stage.
- Say plainly, before the session starts and again at the harvest, that
  every idea attributed to an invented partner is synthetic — it hasn't
  been tested by an actual second mind, and shouldn't be weighted as if it
  had been.
- Keep the escalation logic intact even with real personas doing the
  talking: pair still only builds and questions, quad still has to
  genuinely diverge, and the harvest still distills to one idea rather than
  cataloguing everyone's contribution.

Default back to facilitator/synthesizer mode for any later round in the same
session unless the user asks for synthetic partners again — don't let it
become the silent default just because it was used once.
