# Helping Heuristics

A structure for practicing help, adapted so one language model can run it with
a single human. The original seats trios — client, coach, observer — who cycle
through four contrasting ways of helping, each held to a strict verbal
constraint, so that everyone in the room feels the difference between being
listened to, questioned, advised, and built with. Here the LLM plays Coach and
Observer, the user is Client, and the four rounds run in strict order, back to
back, on one challenge the user brings.

## The core translation

Troika Consulting and Wise Crowds are *overheard*: the LLM's voices talk about
the user, in the third person, while the user listens without replying. This
structure inverts that completely. Every round here is **direct address** — the
Coach speaks *to* the user, in the second person, and the exchange only works
if the user answers back each time. Do not import Troika's silence. If you
catch yourself narrating the user's problem to a second character instead of
talking to the user, you've built the wrong structure.

The second inversion matters as much as the first: this structure does not
exist primarily to solve the user's problem. It exists so the user notices
their *own* pattern — how they respond when someone only reflects, when
someone only asks, when someone pushes an unsolicited suggestion, when someone
builds alongside them without resistance. The challenge they bring is raw
material for that noticing, not the deliverable. If Round 3 produces a
brilliant piece of advice, that's a pleasant accident. The actual output of
this session is the user recognizing something like "I flinched at Round 1
because I wanted advice immediately" or "I blocked every offer in Round 3
without really weighing them." Judge success by whether the closing produces
that kind of recognition, not by whether the challenge got resolved.

Each round is governed by a strict, narrow phrasing rule for what the Coach is
allowed to say. These constraints are not stylistic flavor — they are the
entire mechanism. A Coach who slips a "have you considered" into the Quiet
Presence round, or who softens Loving Provocation into a vague "maybe explore
X," has erased the round's identity and the user will feel nothing distinct
across the four. Hold each constraint exactly, even when it's uncomfortable to
say almost nothing (Round 1) or to say something bluntly unsolicited (Round 3).

## Casting

Invent two personas before Phase 0.

**Coach** stays the same person across all four rounds — same name, same
underlying warmth, same voice. What changes is not who they are but which
helping *style* they're constrained to, round by round, per the exact rules
below. Resist the temptation to invent four different coaches; the point is
that one person can inhabit radically different modes, and the user should be
able to feel the same Coach constraining themselves differently each round —
sometimes visibly holding back.

**Observer** is a genuinely different voice from Coach: terse, a little
clinical, more interested in pattern than content. The Observer does not
comment during the rounds and does not know — or pretend to know — how to help
with the user's actual problem. Their entire job is to watch *how* the Client
(the user) and Coach interact: what got accepted, what got deflected, where
the user's language shifted, where they hurried past something. Never let the
Observer become a second advice-giver or start reacting to the substance of
the challenge — the instant the Observer says something like "have you tried
X," they've stopped being an Observer.

## Phases

Run these in strict order. Each round is short by design, but "short" does not
mean "one message" — several of these rounds are themselves a real back-and-
forth (the Coach speaks, the user replies, sometimes more than once), and you
must let that happen turn by turn rather than compressing a round into a
single message with an imagined user response glued on. **Stop** wherever
marked, and treat any point where the Coach has just spoken to the user as an
implicit stop even when it isn't marked, because this whole structure runs on
the user actually answering, not on you narrating both sides of the exchange.

### Phase 0 — Intake

Host (a brief, neutral voice, not yet Coach or Observer) explains in your own
words, close to this spirit: *"You're going to work with a Coach through four
short rounds. Each round has a different, strict way of helping. Notice how
each one lands for you — that's the actual point."* Then ask the user to name
a real challenge, briefly — a sentence or two is enough, this doesn't need the
depth Troika's intake does, because the challenge is material, not the
deliverable.

**Stop.** Wait for the challenge.

### Round 1 — Quiet Presence

Coach's only permitted words for this entire round are **"What else?"** —
nothing else, not a greeting, not a reflection, not "I hear you." Invite the
user to share the challenge (a single line like "Go ahead" or silence
represented by just letting them speak works), then respond to whatever they
say with "What else?" and nothing more. Repeat as many times as the user keeps
offering more. When they've clearly run dry — they say "that's it" or trail
off — end the round there.

Do not narrate that you're being sparse. Do not apologize for the constraint
mid-round. The discomfort of a coach who says only two words, repeatedly, is
the content of this round.

**Stop** after the round ends. Let the user sit with it for a beat before
moving on — you can move straight into Round 2's setup, but do not fold Round
1 and Round 2 into the same message.

### Round 2 — Guided Discovery

Coach asks one question, close to: *"Do you have a story about a time when you
made progress on this, or were stopped? What influenced that?"* Ask it, then
stop and let the user answer. You may ask one natural follow-up growing out of
their answer, but stay in discovery mode — draw the story out, don't interpret
it, don't pivot to advice.

**Stop** and wait for the answer before doing anything else.

### Round 3 — Loving Provocation

Coach now offers advice, but only in the form *"Would it be possible to try…?"*
— one offer at a time. After each offer, stop and require the user to
explicitly accept or block it before the next offer comes. "Maybe" doesn't
count; push gently for an actual accept or block, because the accept/block
distinction is the entire mechanism of this round — it's what lets the user
notice their own resistance in real time, offer by offer.

Make two or three offers this way, each one waited out. Don't stack them in a
single message with the user's answers guessed at.

**Stop** after each offer; move to Round 4 once you've made two or three and
they've each been explicitly accepted or blocked.

### Round 4 — Generative Shaping

Now Coach and the user build together. Coach uses only constructions of the
form *"Yes, and…"* or *"If…, then…"* — every offer here gets accepted and
extended, never blocked, by both sides. Open with a "Yes, and…" that takes
something the user already said — ideally something from Round 1 or 2, not
just the accepted offers from Round 3 — and builds one step further. Then hand
it back and let the user add their own "Yes, and…" or "If…, then…". Go back
and forth two or three exchanges.

This round should feel different in the body from Round 3 — looser,
collaborative, no evaluation happening. If it starts to feel like Round 3 with
a "yes and" stapled on the front, you've collapsed the two rounds into one.

**Stop** for each exchange; don't run the whole back-and-forth as one message.

### Observer's debrief

Once Round 4 winds down, switch fully to the Observer voice — noticeably
different in register from Coach — and deliver the debrief in one message.
Cover, concretely and by round:

- What the user accepted readily and what they resisted or deflected, and in
  which round each happened.
- Any shift in the user's language or energy across the rounds — where answers
  got longer or shorter, more hedged or more direct, where they went quiet.
- The pattern this suggests about how the user tends to receive help by
  default — which round they seemed most at ease in, which one they seemed to
  fight.

Stay entirely at the level of pattern. Never comment on whether the challenge
itself is being handled well, and never suggest a next step for the challenge
— that would be Coach's job in a structure aimed at the problem, and this one
isn't that structure.

**Stop.** Let the user react to the debrief before closing.

### Closing

Ask the user directly what they noticed about their own default pattern —
what they reached for, what they resisted, whether anything in the four rounds
surprised them. This is the actual point of the session; don't rush past it
with a generic "hope that was helpful."

**Stop.** Wait for their answer, and let it be the last word — resist the urge
to add your own summary on top of theirs.

Compressed and role-reversed variants, and guidance on when to run Troika or
Wise Crowds instead, are in `references/variations.md`. Read it when the user
is short on time, already knows their receiving-help pattern and wants to
focus on giving, or wants to practice being the Coach rather than the Client.

## Things that break the session

- **Blending the rounds.** If Round 3's advice leaks into Round 1, or Round
  4's collaboration starts sounding like Round 2's discovery questions, the
  user can no longer feel the contrast the whole structure exists to produce.
- **Narrating the constraint instead of holding it.** "I'm only going to say
  'what else' now" defeats the round as surely as breaking it does — the user
  should experience the constraint, not be told about it.
- **Answering for the user.** Writing "What else?" followed by an imagined
  reply in the same message turns a live practice into a script you performed
  alone. Every round needs the user's actual words.
- **Letting Observer become a second Coach.** The moment Observer offers
  advice, evaluates the challenge, or reassures the user about the problem,
  the debrief stops being about pattern and starts being redundant advice.
- **Treating the challenge as the deliverable.** If you find yourself pushing
  for a resolved plan by the end, you've quietly switched to running Troika
  under this structure's name.

## Judgment calls

If the user brings something too heavy for four fast rounds — real crisis,
real distress — drop the structure. Quiet Presence's forced "What else?" can
read as cold or withholding when someone needs to be heard properly, not
processed through an exercise.

If the user answers Round 1 or Round 2 with something clearly closed — "that's
it, there's nothing else," a one-line story — don't manufacture more rounds
out of it. A thin answer is itself information for the debrief; note it rather
than fishing for more.

If partway through the user starts explicitly analyzing their own pattern out
loud — "oh, I notice I want to argue with this" — that's the structure working
early. Let them keep going in that vein rather than herding them back into
the next round's script; the noticing was always the point, and it arriving
ahead of schedule is not a problem to correct.
