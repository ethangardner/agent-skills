# Variations

Read this when the user asks for one of these modes, or when a plain live
session isn't the right shape for what they've brought.

## Rehearsal mode — synthetic, secondary, and clearly labeled

**This mode is the one deliberate exception to the "no invented personas" rule
in SKILL.md, and it exists for a different purpose entirely.** The main mode
elicits real information from the user about a real group they belong to.
Rehearsal mode does the opposite on purpose: it invents 1–2 practice "team
member" personas so the user can practice *facilitating* a DAD session — asking
the seven questions in order, holding the pacing, resisting the urge to
answer for someone or jump ahead — before they run the real thing with their
actual team, family, or group.

Nothing an invented persona says in this mode is real information. It is
rehearsal material only, generated to give the user something to practice
against, and it must never be presented, summarized, or later referenced as if
it were real intel about a real group. Label the mode plainly when you offer
or enter it — "this is a practice round with a made-up team, not a real
session" — and say so again in the closing summary, so there is no chance the
user later mistakes a rehearsal transcript for genuine findings.

### When to offer it

Offer rehearsal mode when the user says they want to try hosting a DAD
session before doing it for real, when they're nervous about facilitating one
with an actual team, or when they ask to "practice" or "run a mock DAD."
Don't offer it as a substitute when the user already has a real problem in
hand and is ready to answer as themselves — that's the main mode, and
rehearsal mode would be a strictly worse fit for it.

### How it works

1. Ask the user what kind of group and problem they want to practice
   facilitating around (a rough sketch is enough — "a five-person support
   team that keeps missing a recurring deadline").
2. Invent 1–2 team-member personas with a name and a couple of lines of
   flavor — enough to feel like distinct people, not exhaustive backstories.
   Say plainly that these are invented for practice.
3. The user plays host. You play the persona(s) answering each question in
   character, including realistic hedging, a persona who doesn't have a
   bright spot at Question 4 ("none that I know of" is a fine answer for a
   persona to give too — it's realistic, and it gives the user practice
   handling that response gracefully), and answers that don't perfectly line
   up with each other.
4. After each of the user's questions, answer in character, then — briefly,
   out of character — note anything about their facilitation worth flagging:
   did they ask the question as written, did they answer it for the persona,
   did they skip ahead, did they fill an awkward silence themselves. This
   coaching layer is the actual point of the mode.
5. At the end, give the user direct feedback on their hosting, separate from
   the in-character content, and remind them the persona content itself
   carries no real information forward.

### What doesn't carry over

If the user later starts a real DAD session on the same or a similar-sounding
problem, treat it as a fresh session with no memory of what the rehearsal
personas said. Nothing from rehearsal mode should shape or pre-fill an answer
in the real session — the whole point of the main mode is that the answers
come from the user's actual knowledge of actual people.

## Running DAD again on the same problem

If the first pass didn't surface a real bright spot at Question 4, or the
action in Question 6 didn't stick, it's reasonable to run the structure again
later — after the volunteers from the first round have had time to try
something — rather than pushing harder on the same conversation. A second
pass with fresh answers to "what prevents you" and "do you know anybody" often
lands differently once time has passed and something has actually been tried.

## Solo framing

If the user is the only member of the group with visibility into the problem
(a manager describing a team dynamic they observe but don't personally live
inside), say so before starting, and adjust Question 2 ("How do you contribute
effectively...") to ask instead how they've seen others contribute
effectively — the question still needs to draw out specific, remembered
behavior, just from an observer's vantage point rather than a participant's.
