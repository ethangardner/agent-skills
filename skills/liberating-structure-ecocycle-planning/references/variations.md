# Variations

Read this when the user wants to re-run the structure against ground already
mapped, or wants it run on behalf of a team rather than themselves alone.

## Quarterly reuse

The source material's own suggestion is that an ecocycle map is a snapshot,
not a one-time verdict, and is worth revisiting on a cadence. When the user
returns with a portfolio they mapped in a prior session:

- Start from the prior map rather than Phase 0's from-scratch walkthrough —
  the user already knows the four phases. A one-line reminder of the trap
  definitions is enough.
- Ask what's changed since: what got added, what got dropped, what moved on
  its own without anyone deciding to move it.
- Run the Challenger phase specifically on items that *didn't* move since last
  time, especially anything that was named as trapped last session. An item
  still sitting in the Rigidity Trap two quarters running is a stronger
  finding than a fresh trap identification — it means the action step from
  last time didn't happen, or didn't work, and that's worth naming directly
  rather than quietly re-proposing the same action step again.
- Carry the action-step commitments from the prior session into this one as
  the first thing to check, before mapping anything new. "Last time you said
  you'd wind down X — did that happen?" is often more informative than the
  new map.

## Team or organizational portfolio, via proxy

The structure was designed for a room full of people who each place their own
sticky notes. Run solo on behalf of a team, the user is placing items on
everyone's behalf, which is a real limitation — ask them to explicitly flag
any item where they suspect a colleague would place it differently, and treat
those flagged items as higher-priority targets for the Challenger phase than
items the user is confident about. The disagreement the room would have
surfaced automatically has to be manufactured deliberately here; don't skip
asking for it just because there's no one else to volunteer it.
