# Variations

Read this when the user asks for one of these modes, or when a single open
interview isn't the right shape for what they brought.

## Linked to a current project

Instead of leaving Phase 0 fully open, narrow the invitation toward a success
that happened within a specific project or period the user names: "Tell me
about a time on [project] when you worked with others on something you were
proud of." This is a real facilitation option in the original — anchoring the
prompt to a shared piece of work rather than the user's whole history.

Use it when the user has already brought up a specific project, team, or
period they're trying to understand, rather than asking them to search their
whole past for the first thing that surfaces. It also makes Phase 4's closing
reflection sharper, because "how are you investing in these conditions" has a
concrete, current place to land — the same project the story came from —
instead of staying abstract.

Don't force this by default. If the user's invitation was general, let their
memory pick the story; don't retroactively narrow it once they've already
started telling it.

## Multiple stories, cross-cutting patterns

Run Phases 0 through 2 two or three times on different successes — ideally
ones that feel unrelated on the surface (different team, different era,
different kind of challenge) — before moving to a single, combined Phase 3.

The payoff here is real and different from running one interview: a condition
that shows up in only one story might be circumstance; a condition that shows
up in two or three stories that otherwise share nothing is very likely a
genuine asset the user brings or reliably seeks out, and that's worth more to
name plainly than any single story's details.

Mechanically:

- Run Phase 0–2 for story one in full, including its own played-back
  checkpoint — don't skip that just because more stories are coming.
- Before starting story two, say plainly that you're moving to a second story
  and that you'll come back to patterns across both at the end. Otherwise the
  user may expect Phase 3 after the first story and feel cut off.
- Repeat for a second and, if the user wants, a third story.
- Run a single Phase 3 across all of them: what condition or asset appears in
  more than one story, in different clothing? Naming the same underlying
  condition across dissimilar-looking stories is the actual insight this mode
  exists to produce — don't just recap each story's own conditions
  side by side.
- Phase 4's reflection question stays the same, now aimed at the cross-cutting
  conditions rather than any single story's.

This runs long — treat it as the deliberately deeper option, not the default,
and check with the user before committing to more than two stories.

## Speed version

One story, one round of probing (not two or three), a short played-back
checkpoint, one or two named patterns, and the closing question. Use when the
user wants a quick pass rather than a thorough one, or has already told you
enough of the story unprompted that Phase 0 is effectively answered before
you've asked it.

Resist compressing Phase 2, the played-back checkpoint, even in this version.
It's short by nature already, and it's the point in the structure where a
wrong assumption gets caught before it hardens into Phase 3's pattern-naming.

## When the reflection points somewhere else

If Phase 4 surfaces that the user isn't just under-investing in a known
condition but is actively stuck on a current, unresolved problem, that's a
sign the conversation has outgrown this structure. Say so, and hand off:

- **Troika Consulting or Wise Crowds** if what's needed now is outside
  perspective on a live decision or problem.
- **What I Need From You** if what surfaced is a specific ask the user hasn't
  made of a specific person yet.
- **Discovery and Action Dialogue** if what surfaced is actually a chronic
  problem shared by a real group the user belongs to, where the interesting
  question is who in that group is already handling it well — a different
  question than what conditions enabled the user's own past success.

Don't try to run any of these inside Appreciative Interviews' own closing
phase. Name the shift and let the user decide whether to continue into a
different structure now or stop here with what this one already surfaced.
